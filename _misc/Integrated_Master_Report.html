핵심 요약

항목 내용
목표 단순 질환 분류가 아닌, 의사 판독 기준(Banff 등급)의 순서형 정량 예측 및 설명가능한 CDSS 구축

[!NOTE] 핵심 피벗(Pivot) 및 방향 전환 기존의 단순 병명(예: 급성 신손상) 예측 모델에서 탈피하여, 병리과 의사가 직접 판독하는 기준(섬유화 2단계, 위축 1단계 등)을 순서형으로 평가하는 임상 의사결정 지원 시스템(CDSS)으로 완전히 방향을 전환했습니다. 이는 의사에게 단순한 정답이 아닌, 판독의 근거와 확신도(Confidence)를 제공하기 위함입니다.

1. Introduction (서론)

  • 문제 정의: 기존 모델들은 질환 심각도(0~3등급)를 단순 범주(분류)로 취급해 치명적 오진(예: 0을 3으로 예측)을 발생시켰으며, 블랙박스 구조로 인해 의사결정의 시각적 근거를 제공하지 못했습니다.
  • 연구 가설: 고해상도(40x) 패치에 병리 특화 모델(CTransPath)을 결합하고, 순서형 회귀(CORAL)와 불확실성 제어(Router)를 도입하면 전문의 수준의 일치도(QWK 0.4)를 달성함과 동시에 의사가 1초 만에 검증 가능한 고신뢰성의 시각적 근거(Hotspot)를 제공할 수 있습니다.

2. 파이프라인 아키텍처 (Workflow)

[ 1단계: 데이터 준비 ] SVS 원본 슬라이드 (환자 83명, H&E·PAS·MT·Silver 4종 염색)   ↓ 하얀 여백을 무시하고 실제 조직이 있는 영역만 정확히 찾아내기 (HSV/Otsu 알고리즘)   ↓ 현미경 400배(40x) 수준의 아주 미세한 정사각형 조각(패치)들로 잘게 쪼개기

[ 2단계: 이미지 특징 변환 ] 병리 특화 인공지능(CTransPath) 활용   ↓ 잘게 쪼갠 수만 개의 조직 조각을 컴퓨터가 이해할 수 있는 수학적 수치(임베딩)로 변환해 저장

[ 3단계: 질환 심각도 학습 ] 순서형 진단 인공지능 (ABMIL + CORAL)   ↓ 단순 분류가 아니라, 병이 얼마나 심각한지(0~3등급) '순서와 정도'를 파악하도록 학습   ↓ 섬유화, 위축 등 질환별로 서로 다른 핵심 부위를 찾아보게 만들기 (Task-Attention)

[ 4단계: AI 신뢰성 향상 ] 불확실성 제어 및 다수결 평가   ↓ 5개의 각기 다른 AI 모델의 의견을 종합하여 정확도 높이기 (5-Seed 앙상블)   ↓ AI 스스로 헷갈리거나 확신이 없는 케이스는 무리하게 찍지 않고 걸러내기 (Router 필터링)

[ 5단계: 최종 평가 및 병원 적용 ] 의사결정 지원 시스템 (CDSS v6.1)   ↓ 심각도 평가 성능(QWK) 0.4 달성 및 AI가 진단에 쓴 핵심 증거 부위(핫스팟) 시각화   ↓ 의사용 진단 보조 화면에 AI의 분석 결과와 실시간 히트맵 띄우기 (API 서버 연동)

3. Cohort & Data (코호트 현황)

총 86명의 KPMP AKI 환자 중 83명 확보 (확보율 96.5%). 불확실한 임상 라벨 대신 전문의가 판독한 descriptor_labels.csv의 실제 5종 점수(0~3점)를 사용하여 모델을 학습시켰으며, 5-Fold 교차 검증으로 데이터 누수를 완벽히 차단했습니다.

[!WARNING] ATN(급성 세뇨관 괴사) 제외 사유 및 클래스 불균형 * ATN 배제: KPMP 코호트의 공식 진단명에는 ATN이 존재하지 않으며 ATI(급성 세뇨관 손상)로 분류됩니다. 미세 판독 파일(descriptor_labels.csv)을 전수 조사한 결과, 괴사(Necrosis) 환자는 전체 340명 중 단 10명에 불과해 심각한 라벨 붕괴 우려로 모델 타겟에서 배제되었고, 대신 세뇨관염(AUROC 0.793) 등의 보조 지표가 사용되었습니다. * 섬유화 클래스 쏠림 현상: 데이터의 기형적 편향(0%: 30명, 5%: 40명, 10%: 52명 등 경증 쏠림)으로 인해 95% 신뢰구간(CI)이 넓어지는 현상이 발생했습니다. 이는 알고리즘의 문제가 아닌 데이터 태생적 한계입니다.

코호트 선정 이미지 해석 가이드 * 무엇을 보여주는가?: KPMP 전체 환자 중 본 연구에 적합한 환자를 어떻게 필터링하여 최종 83명을 선정했는지, 그리고 선정된 환자들의 핵심 진단명(ATI, AIN, DKD 등) 분포가 어떻게 구성되어 있는지 보여주는 그래프입니다. * 핵심 포인트: 특정 질환(ATI)에 데이터가 몰려있는 불균형 문제를 시각적으로 파악하고, 이를 해결하기 위해 단순 진단명이 아닌 descriptor_labels.csv의 정량적 평가 점수를 사용하게 된 당위성을 증명합니다.

이미지 해석 가이드 * 무엇을 보여주는가?: 83명 환자의 4가지 염색(H&E, PAS, MT, Silver) 슬라이드 보유 데이터 현황. * 해석 방법: 진하게 칠해진 칸은 완벽 확보를, 하얗게 비어있는 칸은 데이터 누락(결측치)을 의미합니다.

[!CAUTION] 염색 데이터 오염 및 특성 섞임 문제 조치 초기 파이프라인에서 H&E(2-Stain) 전용 알고리즘인 Macenko 정규화를 색상 특성이 완전히 다른 MT, Silver 등의 특수 염색에도 일괄 적용하여, 각기 다른 염색 데이터의 특성이 서로 섞이고 벡터가 오염되는 문제가 발생했었습니다. 이를 해결하기 위해 H&E에는 Macenko를, 특수 염색에는 범용적인 Reinhard 정규화를 분리 적용하도록 파이프라인(embed_patches.py)을 전면 수정하여 데이터 정합성 이슈를 완벽히 해결했습니다.

데이터 증강 비교 한계 및 무결성 문제 (N=78 vs N=83)

[!CAUTION] 데이터 무결성 훼손 오류 발견 및 재실행 조치 당초 N=78 대비 N=83 모델에서 "성능이 극적으로 상승했다"고 평가되었으나, 백업된 평가 로그(ati_exp_compare.csv 및 ati_exp_compare_N78.csv)를 전수 조사한 결과 두 실험 파일의 QWK 점수가 100% 동일하게 덮어쓰기(Overwrite)된 치명적 오류가 발견되었습니다. 이에 따라 2026-06-29, 실제 가상환경(chym_proj conda)을 활용하여 CTransPath 40x 모델(exp5)을 CPU 상에서 전수 재실행(Re-run)하여 실제 통계 지표와 W&B 트래킹 로그를 정상 복구했습니다.

5. 설명 가능성 시각화 (Attention Hotspots)

어텐션 히트맵 해석 가이드 * 무엇을 보여주는가?: AI가 최종 진단을 위해 가장 결정적인 증거로 삼은 핵심 부위(핫스팟) 시각화. * 해석 방법: 빨간색/노란색 부위가 AI가 병변을 정확히 찾아내어 집중적으로 쳐다본 곳입니다. 특히 섬유화 예측 시 인공지능이 스스로 4가지 염색 중 MT 염색 슬라이드에만 집중하는 의학적으로 완벽한 교과서적 패턴을 보여주었습니다. * 우측 확대 사진(Top-16): AI가 가장 붉게 칠한 상위 16곳의 실제 원본 세포 조직(400배 확대)입니다. 잡음(Artifact)이 아닌 실제 세뇨관(Tubule) 손상 부위를 정확히 추출했음이 입증되었습니다.

6. 백엔드 연동 상태 (Fully Integrated)

본 모델은 단순 연구 수준을 넘어, 실제 FastAPI 백엔드 서버와 React 프론트엔드에 E2E(End-to-End) 연동이 완료되었습니다.

  • Adapter 패턴 연동: 백엔드의 cdss_engine_adapter.py가 Pytorch 추론 코드를 직접 래핑(Wrapping)하여, 분석 요청 시 실제 .pt 가중치를 바탕으로 추론을 수행합니다.
  • CDSS v6.1 3-Layer 패널 연동 완료:
  • [ Layer 1 ] EMR 기반 AKI 48시간 위험도
  • [ Layer 2 ] 핵심 임상 3축 (섬유화/위축/염증) 예측 게이지
  • [ Layer 3 ] 본 연구의 상세 Descriptor 점수 (0~3점) 및 AI 불확실성(마진) 수치

7. 한계점 및 상용화 아키텍처 보완 제안

모델이 서버에 무사히 연결되어 동작하고 있으나, 대형 병원의 상용 서비스(Production) 수준으로 스케일업하기 위해 다음의 엔지니어링 보완이 요구됩니다.

  1. ML 추론 파이프라인의 비동기 워커 분리: 현재 FastAPI 내에서 동기(Synchronous) 처리 중인 무거운 Pytorch 연산을 Celery/RabbitMQ 등을 통해 백그라운드 GPU 워커로 분리해야 다중 접속 시 서버 마비를 막을 수 있습니다.
  2. WSI 스트리밍 성능 최적화: 뷰어의 버벅거림을 막기 위해, SVS 파일 업로드 즉시 백그라운드에서 전체 피라미드 타일을 사전 렌더링(Pre-computation)하거나 Redis 캐싱을 도입해야 합니다.
  3. 입력 데이터 품질 검증망(QC): 염색 불량이나 초점이 나간 슬라이드가 AI에 유입되지 않도록, 추론 직전 영상 품질을 검사하여 조기 거부(Early Reject)하는 파이프라인이 필수적입니다.
  4. 오브젝트 스토리지 격리: 로컬 파일 경로에 결합된 모델 가중치 파일들을 AWS S3 등으로 분리하고 MLflow로 관리하여 서버 스케일아웃 환경을 대비해야 합니다.
